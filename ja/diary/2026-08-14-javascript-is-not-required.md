始まりは、Smalltalk-2030 のページを**自然に読み上げたい**という話だった。

サイトはもともと、かなり強い方針を持っていた。

> JavaScript なし

Jekyll だけで作り、画像も外部フォントも使わず、テキストを中心にする。<br>
**読めること、コピーできること、直せることを優先する。**

ところが、ブラウザには `speechSynthesis` がある。

JavaScript を少し使えば、ページそのものに「🔊 このページを読む」という機能を載せられる。

ここで、方針と機能が衝突した。

しかし、よく考えると衝突していなかった。

大事なのは、**JavaScript を使わないこと**ではない。<br>
**JavaScript がなければ読めないサイトにしないこと**だった。

そこで方針を、こう書き換えた。

> **JavaScript を必須にしない（読み上げなどの補助機能には使用可）**

JavaScript を切っても、本文は読める。<br>
リンクはたどれる。<br>
テキストはコピーできる。

JavaScript が動く環境なら、その上に読み上げのような機能を足す。

本体を JavaScript に預けるのではなく、**すでに成立している HTML を JavaScript が少し助ける。**

いわゆる progressive enhancement だが、ここでは名前より順序のほうが大事だった。

まず、人間が読めるページがある。<br>
そのあとで、機械が少し便利にする。

実装した読み上げも、その考えに従った。

`speechSynthesis` に対応しているブラウザだけでボタンを出す。<br>
対応していなければ、何もしない。

読み上げる対象も、画面にある文字を無差別に全部読ませるのではなく、本文を中心にする。ナビゲーション、QR コード、短縮 URL などは外せるようにし、必要なら `data-speak` と `data-no-speak` で人間が制御できるようにした。

そして、さらに欲が出た。

ブラウザ標準の声ではなく、**Gemini に喋らせたい。**

ここでも同じ原則が働く。

Gemini の API キーをブラウザの JavaScript に埋め込んではいけない。使うならサーバー側の入口を用意し、そこから Gemini を呼ぶ。

だが、Gemini が止まってもページは読める。<br>
音声機能が壊れても、文章はそこに残る。

この日、「JavaScript なし」という一見単純な禁則は、少しだけ姿を変えた。

**禁止から、非依存へ。**

使ってはいけないのではない。<br>
なくても成立するように作る。

Smalltalk-2030 が人間をコンピューターへ従わせないのなら、Web ページもまた、特定の実行環境へ人間を従わせる必要はない。

JavaScript はいてもいい。<br>
ただし、いなくても困らない。
